# 双人战斗样板：八方向、双手柄与手感约定

日期：2026-09-18。已选美术：D「极简豆豆冒险」。
状态：本文件保留初始实现约定。已完成的可玩样板与验证范围见项目 README.md；实体手柄与真实双人手感仍待验收。下文“当前样板差距”是实施前的历史审查记录。

## 1. 八方向与素材

采用八方向视觉朝向。键盘提供八方向输入；手柄保持连续角度、连续速度，移动向量与命中计算不量化为八个方向。只有角色动画选择八方向。

像指针连续转动，而角色选取最近的一张朝向动画：视觉八方向不意味着操作只能沿八条线移动。

- 待机与跑动：八方向，统一脚底锚点与人物比例；转方向不重置步态相位。
- 普攻、盾冲、定向施法、弓箭动作：八方向身体与装备姿态；投射物方向连续计算，发射点来自对应姿态的武器/手部锚点。
- 闪避：八方向姿态，实际位移沿连续输入向量；松开方向时沿最后有效移动方向，避免自动锁敌把闪避带向敌人。
- 旋风斩、冰霜环：人物仍有朝向，圆形特效可复用，不制作八份相同圆环。
- 受击、倒地：首版可用少量方向姿态与受击偏移，之后按可读性补齐。
- 身体、脸/头饰、主手武器、副手装备、地面影子、特效分别管理遮挡。允许按方向共用部件，不能直接镜像整个战士造成左右手交换。
- D 风格使用统一结构制作动画与必要的手工关键姿态；生成图负责确定观感，不把逐张生成的图片直接拼成动画。
- 第一交付仍为战士八方向跑动、移动普攻、盾冲和闪避；验收通过再扩展另外两职业。
- 攻速、移速分别驱动攻击时间轴与步态；动作命中事件独立于图像帧，低帧率跨过命中时刻也只结算一次。
- 慢速转动摇杆穿过方向边界时增加小幅角度滞回，避免两张朝向反复闪烁；阈值需在样板调试。

## 2. 双人输入与后续双手柄

本轮测试组合为 P1 键盘 + P2 手柄。双手柄为明确的后续需求，输入设计现在兼容两个玩家槽位，后续做实际设备接入和验收；不得宣称已经支持。

输入流：设备 -> 玩家槽位 -> move / skill1 / skill2 / dodge / confirm / pause。
角色逻辑不直接读取键盘键码、手柄序号或 Xbox 按钮名。

- 槽位可绑定键盘或一只手柄，设备独占，不允许一只手柄驱动两位玩家。
- 加入时按键认领未占用槽位；P1 可以绑定手柄，不能永久写死为键盘。
- 支持两只同型号手柄；不能仅凭设备名称区分。
- 手柄断开时清除该玩家持续输入，暂停并提示重新绑定；不能因设备数组重排把控制权转给队友。
- 重连需确认归属；手柄 index 只作为当前连接句柄，不作为跨重连稳定身份。
- 圆形死区从 0.18 起调，死区之外重新映射推幅到 0–1；轻推慢走，满推正常速度。
- 键盘斜向归一化；手柄保留模拟量，不能把所有非零向量归一化为满速。
- 按键提示根据当前绑定设备与布局生成；确认和战斗动作按界面模式隔离，按键释放后再接受新上下文，避免确认升级后意外闪避。
- 双人各自导航自己的升级卡片；断线不能悄悄变为 AI 或自动替玩家确认。
- 实机验收需包括两只实体手柄同时移动、交叉释放技能、同帧确认、拔插、焦点丢失与恢复。模拟输入测试不能替代硬件验证。
- 震动仅在支持设备上启用，不把震动可用性作为操作正确性的前提。

## 4. 手感初值与规则

这些是设计初值，需在战士样板中调试与实测，不能按固定数字直接宣告“手感合格”。

| 项目 | 第一轮规则与初值 |
|---|---|
| 响应 | 输入采样后下一模拟步消费，目标 60Hz（每步约 16.7ms）；这是逻辑预算，不等于实体按键到屏幕的总延迟 |
| 输入缓存 | 闪避/技能约 100–150ms 的短缓存；只在合法窗口执行一次，过期丢弃，暂停/断线清空 |
| 动作取消 | 闪避可取消普攻前后摇；被取消的未来命中不得补算；主动技能按明确的取消窗口执行 |
| 闪避 | 总动作先试 250–320ms，无敌窗口先试 100–160ms；固定方向，墙体阻挡，冷却和无敌按模拟时间推进 |
| 自动普攻 | 不自动追敌走路，不强迫停步；一次攻击锁定目标/方向，不在挥击中来回转头；下一次攻击才重新选敌 |
| 目标选择 | 优先有效攻击范围内、方向合理且无遮挡的敌人，设置切换稳定性；不把远处敌人当作闪避方向 |
| 命中反馈 | 命中音、受击亮色、短促压缩形变、定向小击退；强弱攻击分层，粒子不遮危险预警 |
| 命中顿帧 | 先试命中双方表现层 30–50ms 短停，普通自动攻击不冻结全局或队友输入；碰撞、无敌和冷却时钟不能因此漂移 |
| 震屏 | 小幅、衰减、有强度上限和关闭选项；不随每个自动普攻累加全屏震动 |
| 敌人预警 | 普通样板攻击先试 350–600ms 可见预警；攻击方向/范围与真实判定一致，之后按敌人类型调节 |
| 共享镜头 | 跟踪双人包围范围，留边距与缩放滞回，避免每步呼吸式缩放；镜头到边界时不突然把玩家拉回 |
| 音效 | 出招与命中区分，少量音高/音量变化；限制密集命中的叠音数量，关闭视觉特效后仍能分辨命中 |

## 5. 与当前样板的差距

本轮查看 src/model.js 得到：
- 已有八方向选帧、上下身分层、移动中普攻和固定时间步相关基础。
- 闪避/盾冲用 direction() 将输入量化到八方向，再由 vector() 位移：正式双人版需保留连续动作方向。
- 普通移动将非零输入除以长度，因此无法保留手柄轻推速度：需要死区处理后保留强度。
- 盾冲/闪避过程中 trigger() 直接拒绝新动作，尚无上述短缓存与详细取消窗口。
- 当前是战士样板，没有双玩家输入路由、AI、真实敌人伤害与无敌窗口。这些是待实现项。

## 6. 验收清单

- 八方向逐帧检查：装备不换手、脚点不漂、连续切方向不重置步态、背面遮挡正确。
- 同一输入序列在 30/60/120 FPS 下验证位移、伤害次数、冷却与无敌窗口近似一致；记录允许误差与卡顿策略。
- 自动普攻中按闪避：在允许窗口响应，取消的命中不会延迟发生；缓存边界及重复按键都有回归测试。
- 手柄 360° 扫动：移动无方向吸附，动画朝向稳定；轻推慢走，松手不漂，斜向不更快。
- 一人持续命中，一人移动/闪避：后者输入和动作不会被前者顿帧打断。
- 两人拉开/靠近：均保持在安全可视范围，镜头不骤跳、不抖动、不遮关键 HUD。
- 升级独立选择与确认，所有人就绪才继续；暂停和界面切换不会漏入战斗输入。
- 键盘+手柄先验收，后续双实体手柄再单独验收，测试报告分开记录。
- 先关闭特效判断控制和命中，再逐项开启反馈并进行双人试玩；流畅与好玩需玩家实际体验验收，不仅靠测试通过。
